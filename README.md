# Sub Bot — Telegram-бот лид-магнита

Бот выдаёт файл-подарок в обмен на подписку на канал.

- `/start` → бот предлагает подписаться на канал;
- после подписки (кнопка «Я подписался») бот проверяет членство и выдаёт файл;
- неподписавшимся бот шлёт напоминания по настраиваемому конечному расписанию;
- админ заменяет файл-подарок командой `/setfile`.

## Стек

- Python 3.12 + [aiogram 3](https://docs.aiogram.dev) (long polling, без вебхука)
- PostgreSQL 16 — отдельная схема (`sub_bot`), существующие таблицы не затрагиваются
- Redis — FSM-состояния и кеш проверки подписки
- APScheduler — планировщик напоминаний и проверки подписок (замена крона)
- Docker + docker compose
- GitHub Actions — автодеплой по push в `master`

## Как это работает

```
/start
  ├─ подписан?  ──да──► отметить подписку ─► отправить файл
  └─ нет ─► сообщение + кнопки [Подписаться] [Я подписался]
                                              │
                          нажал «Я подписался»─► повторная проверка ─► выдать файл / «ещё не подписан»

Планировщик (каждые N минут):
  для каждого, кто не получил подарок и лимит напоминаний не исчерпан:
    срок очередного напоминания подошёл?
      ├─ подписался сам ─► выдать файл
      └─ нет ─► отправить напоминание (#k из N), после последнего — больше не беспокоить
```

## Команды

| Команда            | Кто     | Действие                                            |
|--------------------|---------|-----------------------------------------------------|
| `/start`           | все     | старт воронки, проверка подписки, выдача файла      |
| `/admin`           | админ   | список всех админских команд                        |
| `/setfile`         | админ   | заменить файл лид-магнита (бот попросит файл)        |
| `/cancel`          | админ   | отменить замену файла                               |
| `/reset`           | админ   | сбросить себя для повторного теста сценария с нуля  |
| `/reset <user_id>` | админ   | сбросить конкретного пользователя по id             |
| `/setreminders`               | админ | показать текущее расписание напоминаний          |
| `/setreminders 5m,24h,72h`    | админ | задать расписание на лету (сохраняется в БД)     |

## Переменные окружения

Скопируйте `.env.example` в `.env` и заполните:

| Переменная                    | Обязательна | Описание |
|-------------------------------|:-----------:|----------|
| `BOT_TOKEN`                   | да          | Токен бота от [@BotFather](https://t.me/BotFather) |
| `CHANNEL_ID`                  | да          | Канал для проверки: `@username` или `-100123456789` |
| `CHANNEL_URL`                 | нет         | Ссылка для кнопки «Подписаться». Для `@username` собирается автоматически; для приватного канала укажите инвайт-ссылку |
| `ADMIN_IDS`                   | да          | ID админов через запятую (доступ к `/setfile`). Узнать свой id: [@userinfobot](https://t.me/userinfobot) |
| `DATABASE_URL`                | да          | DSN существующего Postgres |
| `DB_SCHEMA`                   | нет         | Схема под бот (по умолчанию `sub_bot`, создаётся сама) |
| `REDIS_URL`                   | нет         | По умолчанию `redis://localhost:6379/0` |
| `REMINDER_INTERVALS`          | нет         | Список интервалов от `/start` через запятую. Кол-во = число напоминаний. Суффиксы: `m`/`h`/`d`. По умолчанию `1h,24h,72h` |
| `REMINDER_CHECK_INTERVAL_MIN` | нет         | Период опроса планировщика, мин (по умолчанию `5`) |
| `SUB_CACHE_TTL`               | нет         | TTL кеша подписки, сек (по умолчанию `60`) |
| `LOG_LEVEL`                   | нет         | `DEBUG`/`INFO`/`WARNING`/`ERROR` |

### Про напоминания

Число напоминаний **конечно** и равно количеству значений в `REMINDER_INTERVALS`.
Каждое значение — смещение от момента нажатия `/start`.

Пример `REMINDER_INTERVALS=1h,24h,72h`:
- напоминание №1 — через 1 час после старта;
- напоминание №2 — через 24 часа;
- напоминание №3 — через 72 часа;
- после третьего бот больше не беспокоит пользователя.

Хотите 5 напоминаний раз в 12 часов — поставьте `12h,24h,36h,48h,60h`.

`REMINDER_INTERVALS` из `.env` — это значение **по умолчанию**. Админ может поменять
расписание на лету командой `/setreminders 5m,24h,72h` (сохраняется в БД, применяется
без перезапуска и переживает рестарт). Текущее значение: `/setreminders` без аргументов.

## Подготовка бота и канала

1. Создайте бота у [@BotFather](https://t.me/BotFather) → получите `BOT_TOKEN`.
2. **Сделайте бота администратором канала** — иначе Telegram не даёт проверять подписку.
3. Узнайте `CHANNEL_ID`:
   - публичный канал — просто `@username`;
   - приватный — переслайте любой пост из канала [@userinfobot](https://t.me/userinfobot) и возьмите id вида `-100...`.

## Запуск

### Через Docker (рекомендуется)

Postgres и Redis уже должны работать (в вашем случае — в Docker на сервере).

```bash
cp .env.example .env   # заполнить
docker compose up -d --build
docker compose logs -f
```

`network_mode: host` в `docker-compose.yml` позволяет боту достучаться до
Postgres/Redis по `localhost`, если их порты опубликованы на хост. Если Postgres/Redis
доступны только во внутренней docker-сети — см. комментарии в `docker-compose.yml`
(подключение бота к внешней сети по имени).

### Локально (без Docker)

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить
python -m src.main
```

Миграции применяются автоматически при старте.

## Деплой на Ubuntu-сервер

### Вариант 1. Автоустановка одной командой

На сервере:

```bash
curl -fsSL https://raw.githubusercontent.com/dimatolpygin/sub_sub/master/scripts/install.sh -o install.sh
bash install.sh
```

Скрипт спросит репозиторий, токен, канал, доступы к БД/Redis, расписание напоминаний,
создаст `.env` и поднимет контейнер.

### Вариант 2. CI/CD (автодеплой при пуше в master)

Деплой выполняет workflow `.github/workflows/deploy.yml`: по push в `master` он
заходит на сервер по SSH, делает `git reset --hard origin/master` и
`docker compose up -d --build`.

#### Шаг 1. SSH-ключ для GitHub Actions

GitHub Actions заходит на сервер по **приватному ключу**, публичная часть которого
лежит на сервере. Сгенерируйте отдельную пару ключей (на любой машине):

```bash
ssh-keygen -t ed25519 -C "github-actions-sub-bot" -f deploy_key -N ""
```

Получите два файла:
- `deploy_key` — приватный ключ (пойдёт в GitHub Secret, **никому не показывать**);
- `deploy_key.pub` — публичный ключ (пойдёт на сервер).

Добавьте публичный ключ на сервер (в пользователя, под которым деплоим):

```bash
ssh-copy-id -i deploy_key.pub user@SERVER_IP
# или вручную:
cat deploy_key.pub >> ~/.ssh/authorized_keys
```

#### Шаг 2. Секреты в репозитории GitHub

`Settings → Secrets and variables → Actions → New repository secret`:

| Secret            | Значение | Пример |
|-------------------|----------|--------|
| `SERVER_HOST`     | IP/домен сервера | `123.45.67.89` |
| `SERVER_USER`     | пользователь SSH | `root` |
| `SSH_PRIVATE_KEY` | содержимое файла `deploy_key` целиком | `-----BEGIN OPENSSH PRIVATE KEY----- ...` |
| `SERVER_PORT`     | порт SSH (необяз., по умолчанию 22) | `22` |
| `INSTALL_DIR`     | каталог на сервере (необяз., по умолчанию `/opt/sub_bot`) | `/opt/sub_bot` |

#### Шаг 3. Первичная установка на сервере

Один раз выполните автоустановку (Вариант 1) на ветке `master`, чтобы каталог
`/opt/sub_bot` существовал и `.env` был создан. Дальше каждый push в `master`
будет автоматически обновлять и перезапускать бота.

> Ветки: `dev` — разработка, `master` — продакшен (на него настроен автодеплой).
> Мержите в `master`, когда готовы к выкату.

## Структура проекта

```
sub_bot/
├─ src/
│  ├─ main.py            # точка входа: БД, Redis, миграции, polling, планировщик
│  ├─ config.py          # настройки из .env (pydantic-settings)
│  ├─ logger.py          # логирование в терминал (на русском)
│  ├─ db.py              # пул Postgres (изоляция по схеме)
│  ├─ migrator.py        # автоприменение SQL-миграций при старте
│  ├─ repo.py            # запросы к БД (users, lead_magnet)
│  ├─ cache.py           # Redis-клиент для кеша
│  ├─ keyboards.py       # inline-клавиатуры
│  ├─ texts.py           # тексты сообщений
│  ├─ middlewares.py     # логирование всех действий пользователей
│  ├─ scheduler.py       # напоминания и проверка подписок (APScheduler)
│  ├─ services/
│  │  ├─ subscription.py # проверка подписки + кеш
│  │  └─ gift.py         # выдача файла-подарка
│  └─ handlers/
│     ├─ start.py        # /start и кнопка «Я подписался»
│     └─ admin.py        # /setfile, /cancel
├─ migrations/0001_init.sql
├─ scripts/install.sh    # автоустановка на Ubuntu
├─ .github/workflows/deploy.yml
├─ Dockerfile
├─ docker-compose.yml
└─ .env.example
```
